# bluetooth

[English](README.md) | 中文

| 需要 | 得到 |
|---|---|
| `Link`：UART（`Uno::UnoSoftSerial<RX_PIN, TX_PIN, BAUD, RX_SIZE>`：任兩隻腳，D0 / D1 留給 USB；或 D0 / D1 上 `Uno_serial_buffer.h` 的 `Uno::UnoSerial<BAUD, RX_SIZE, TX_SIZE>`）；`Key`（EN 是 KEY）或 `Power`（EN 是電源開關）：輸出腳（`Uno::UnoOutputPin<PIN>`）；`State`：接 STATE 的輸入腳（`Uno::UnoInputPin<PIN>`）；每隻腳都可以是 `bluetooth::NoPin` | `bluetooth::HC05`：收發，透過 EN 用 AT 命令設名稱、PIN、鮑率、角色；`bluetooth::HC06`：一樣，但沒有 EN / KEY；`bluetooth::BT05`：BLE 模組（FFE0 / FFE1），UART 那邊一樣；`bluetooth::Port`：任何模組，本身也是 Link；`bluetooth::Packet`：在位元組流上收發有 CRC-8 的封包 |
| 電腦：Python 3，`pip install pyserial`（BLE：再 `pip install bleak`） | `source/packet.py`：透過藍牙序列埠或 BLE 收發同樣的封包；`source/ble.py`：把 BLE 模組當序列埠用 |

「需要」是介面（duck typing），括號裡是這個專案現成的實作，換主板只要換它們。開發者看的細節（前提條件、介面需求、每個函式、參數、資源）在 [INTERFACE.md](INTERFACE.md)。

藍牙序列模組（SPP），`namespace bluetooth`。藍牙的事全由模組自己做（被找到、配對、連線）；板子只看到一個 UART，電腦只看到一個序列埠。板子寫進模組 RXD 的東西會從電腦的序列埠出來，反過來也一樣。資料的格式由程式自己決定：`Packet` 是其中一種。

```
板子  ──TXD/RXD──  模組  ~~ 無線電（RFCOMM / SPP）~~  電腦：一個序列埠（/dev/cu.HC-05、COM5）
```

## 用法

```cpp
#include "Uno_pin.h"
#include "Uno_soft_serial.h"
#include "bluetooth.h"

constexpr uint8_t BT_RX_PIN = A0;           // <- 模組的 TXD
constexpr uint8_t BT_TX_PIN = A1;           // -> 模組的 RXD（經分壓）
constexpr uint8_t KEY_PIN = 12;
constexpr uint8_t STATE_PIN = 4;
constexpr uint32_t BAUD = 9600;             // 模組的資料鮑率
constexpr uint16_t RX_BUFFER = 64;          // loop() 忙的時候中斷先收起來的 byte

using Link = Uno::UnoSoftSerial<BT_RX_PIN, BT_TX_PIN, BAUD, RX_BUFFER>;
using Bluetooth = bluetooth::HC05<Link, Uno::UnoOutputPin<KEY_PIN>, Uno::UnoInputPin<STATE_PIN>>;

void setup() {
    Bluetooth::init();                      // UART、EN LOW（資料模式）、STATE
    Bluetooth::setName("UnoKits");          // AT 命令：EN HIGH、送命令、等回答、EN LOW
    Bluetooth::setPin("1234");
}

void loop() {
    if (Bluetooth::isConnected() && Bluetooth::available()) {
        uint8_t byte;
        Bluetooth::read8(byte, 0);
        Bluetooth::write8(byte);            // 送回去
    }
}
```

全部是 static，所以用 `Bluetooth::` 不用宣告變數。函式庫不管拿到的是哪一種 UART：見[接哪些腳](#接哪些腳軟體-uart-或-d0--d1)。每個 AT 函式回傳 `OK`（0）或錯誤碼（見[結果](#結果)）。完整的例子：`src/week_9_bluetooth/tests/1_HC_05.cpp`、`2_HC_06.cpp`（USB ↔ 藍牙的橋），電腦端是 `round_trip.py`。

## 接哪些腳：軟體 UART 或 D0 / D1

| | `Uno::UnoSoftSerial<RX_PIN, TX_PIN, BAUD, RX_SIZE>`（`Uno_soft_serial.h`） | `Uno::UnoSerial<BAUD, RX_SIZE, TX_SIZE>`（`Uno_serial_buffer.h`） |
|---|---|---|
| 腳位 | 任兩隻；RX 用它那組的腳位改變中斷 | 只能 D0 / D1：硬體 UART，和 USB 共用 |
| 上傳、`pio device monitor` | 模組接著也能用 | 上傳要拔模組的 TXD；不能用 monitor |
| 速度 | 1200 ～ 38400 鮑（超過 19200 有警告） | 都可以 |
| 送 | 9600 鮑每個 byte 等約 1 ms | 送出緩衝區：馬上回來 |
| 適合 | 試東西、同時在 USB 上印（`src/week_9_bluetooth`） | 做好的成品，用電池、不接 USB |

只改 `using Link = …`；`HC05`、`HC06`、`Packet` 都不用改。完全沒有緩衝區（`Uno_serial.h` 的 `Uno::UnoSerial<BAUD>`）也能用，但 UNO 只存 2 個收到的 byte：`loop()` 絕不能忙太久。

## HC-06：沒有 EN / KEY

```cpp
using Bluetooth = bluetooth::HC06<Link>;                                   // 4 腳
using Bluetooth = bluetooth::HC06<Link, Uno::UnoInputPin<STATE_PIN>>;      // 6 腳：也接 STATE
```

- **只有沒連線時才收 AT 命令**：電腦一連上，每個位元組都是資料。在 `setup()` 裡、一上電就送。
- **每條大約一秒**：HC-06 用停頓判斷命令結束，所以 `HC06` 兩條命令之間會等 `GAP_MS`。
- **有接 STATE** 時，連線中 AT 函式回傳 `ERROR_CONNECTED`，什麼都不送；沒接就分辨不出來，命令會變成文字送到電腦。

函式和 `HC05` 一樣，只是沒有 `setRole()`、`restart()`（HC-06 沒有這些命令）。

## BT05：BLE（HM-10 那一類）

```cpp
constexpr uint8_t EN_PIN = 12;              // EN：這塊板子的電源開關
using Bluetooth = bluetooth::BT05<Link, Uno::UnoInputPin<STATE_PIN>, Uno::UnoOutputPin<EN_PIN>>;
```

有些長得像 HC-05 的板子上面其實是 BLE 模組（`AT+UUID` 回答 `+UUID=FFE0`）。UART 那一邊一樣，所以 `Port`、`Packet`、接線都不變；無線電那一邊不一樣：

| | HC-05 / HC-06（傳統，SPP） | BT05（BLE） |
|---|---|---|
| 在電腦上 | 配對一次，然後是一個序列埠（`/dev/cu.NAME`、`COM5`） | 沒有序列埠：用名稱以 GATT 連線，service FFE0、characteristic FFE1（`source/ble.py`，`pip install bleak`） |
| 配對 | 需要（PIN） | 不需要 |
| iPhone | 不行（iOS 沒有 SPP） | 可以（任何 BLE 終端機 App） |
| 一次寫入 | 任何長度 | 最多 20 bytes（`ble.py` 會切段並控制速度） |
| AT 命令 | `module/HC_05.h`、`HC_06.h` | `module/BT05.h`：`AT+NAMExxx`、6 位數的 `AT+PIN`、`AT+BAUDn`、`AT+VERSION`、`AT+LADDR` |

- **AT 命令只在沒連線時有效**，和 HC-06 一樣；有接 STATE 時，連線中 AT 函式回傳 `ERROR_CONNECTED`。
- **剛改完名稱**時模組會有一段時間不理命令（它在重設廣播）：完全沒有回答時 `BT05` 會再送一次（`RETRY_MS`、`TRIES`）。
- **EN 當電源開關**：量過的這塊板子，EN 把模組打開（HIGH）、關掉（LOW），不驅動時維持原本的電位。`Power` 從 `init()` 起一直保持 HIGH；`setPower(false)` 關掉模組。同樣接法的 HC-05 板子：`bluetooth::HC05PowerSwitch<Link, En, State>`，或用 `HC05ByEn<Link, En, State, EN_IS_POWER>::Type` 以 bool 選。`src/week_9_bluetooth/tests/3_diagnose.cpp` 會告訴你板子是哪一種。

## 任何模組：Port

```cpp
using Bluetooth = bluetooth::Port<Link>;                                       // 只接 TXD / RXD
using Bluetooth = bluetooth::Port<Link, bluetooth::NoPin, Uno::UnoInputPin<STATE_PIN>>;
```

`Port` 是 UART 加上那兩隻可選的腳，沒有任何特定模組的東西：收發、`isConnected()`、`setCommandMode()`。沒接 EN 的 HC-05，或其他 SPP 模組，都可以用它。`Port`（所以 `HC05`、`HC06` 也是）本身就是 Link：`stream::Puller<Bluetooth, CHUNK>` 也能透過藍牙拉檔案。

## 封包

藍牙序列只給位元組：一個封包可能分好幾次到，也可能兩個黏在一起。`Packet` 加上封包從哪裡開始、多長，和 CRC：

```
┌──────┬────────┬─────────┬───────────────┬──────┐
│ 0xAA │ LENGTH │ COMMAND │ DATA (LENGTH) │ CRC  │
└──────┴────────┴─────────┴───────────────┴──────┘
 START   0 ～ 255  任何位元組  數字：低位元組    LENGTH、COMMAND、每個 DATA 位元組的
                  （'L'）    在前             CRC-8（多項式 0x07，起始 0）
```

```cpp
bluetooth::Packet<Bluetooth, PACKET_MAX_LENGTH> packets;

packets.init();                                 // 也會 Bluetooth::init()
// 在 loop 裡：
if (packets.update()) {                         // 一直呼叫，它不會等
    if (packets.command() == 'M') {
        int16_t left = packets.readInt16(0);    // DATA 第 0、1 個位元組
        int16_t right = packets.readInt16(2);   // DATA 第 2、3 個位元組
    }
}
packets.sendText('S', "ready");                 // 送給電腦
```

| 函式 | 做什麼 |
|---|---|
| `update()` | 讀已經到的東西；收到一整個 CRC 正確的封包時回傳 true |
| `command()`、`length()`、`data()` | 這個封包，到下一次 `update()` 前都有效 |
| `readUint8(i)`、`readInt8(i)`、`readUint16(i)`、`readInt16(i)` | 從 DATA 第 `i` 個位元組讀數字（兩個位元組的低位在前）；超過長度是 0 |
| `send(command, data, length)`、`sendText(command, text)` | 送一個封包 |
| `dropped()` | 丟掉的封包數：CRC 錯、太長、或斷掉 |

- 壞掉的封包會被丟掉，從下一個 `0xAA` 重新開始：掉一個位元組只會掉一個封包，不會影響後面的。
- `Packet` 收任何 Link：`Packet<Uno::UnoSerial<BAUD>>` 透過 USB 收發同樣的封包。

### 電腦：packet.py

```bash
pip install pyserial
python lib/bluetooth/source/packet.py --list                  # 列出序列埠，藍牙的有標記
python lib/bluetooth/source/packet.py --port /dev/cu.UnoKits  # 接著打封包
python lib/bluetooth/source/packet.py --ble TanksUno          # BLE（BT05）：用名稱，pip install bleak
python lib/bluetooth/source/ble.py --scan                     # 附近的 BLE 裝置，標出 FFE0 的
```

macOS 第一次會要求允許終端機程式（Terminal、iTerm、VS Code）使用藍牙；不允許的話永遠找不到 BLE 裝置。

```
L 1                  'L' 帶一個位元組 1
M h:200 h:-100       'M' 帶兩個 int16（低位元組在前，和 readInt16 一樣）
E s:hello            'E' 帶 "hello" 的位元組
[BOARD] 'S' 5 bytes: 72 65 61 64 79  "ready"
```

| 輸入 | 位元組 |
|---|---|
| `200`、`-5` | 一個位元組（0 ～ 255、-128 ～ -1） |
| `h:-100`、`H:500` | 兩個位元組，int16 / uint16，低位在前 |
| `s:text` | 文字的位元組 |

在自己的 Python 裡，`packet.py` 的 `encode(command, data)`、`Decoder().feed(bytes)` 和 `crc8(bytes)` 做出、讀取同樣的封包。

## 抗干擾

錯誤從好幾個地方來；每一層擋自己的：

| 層 | 出什麼錯 | 誰擋 |
|---|---|---|
| 線（TXD / RXD） | 馬達、長線、浮接的 RXD：位元被翻掉 | 分壓電阻拉住 RXD；共地；模組 VCC 旁加 100 nF + 10 µF；線短、遠離馬達線 |
| UART | 壞掉的 byte（停止位元不是 HIGH） | `UnoSerial` 丟掉，`brokenCount()` |
| UART | `loop()` 在忙，byte 沒及時讀 | 接收緩衝區（`RX_SIZE`）：中斷先收起來；還是太多：`lostCount()` |
| 無線電 | 2.4 GHz 的干擾 | 藍牙自己：每個無線封包都有自己的 CRC，沒到就重送（不用做什麼） |
| 封包 | 掉一個 byte、被改、兩個黏在一起 | `Packet`：START、LENGTH、CRC-8（擋住所有 1 ～ 2 位元錯誤、8 位元以內的連續錯誤）、`GAP_MS`；丟掉，`dropped()`；從下一個 START 重新開始 |
| 程式 | 封包被丟掉 | 每個命令都回答（像 `L` → `L`）：電腦沒收到回答就重送 |

所以透過藍牙時，無線電本身是安全的；會壞的幾乎都是板子和模組之間的線，或板子讀得太晚。

## STATE：有沒有連線

```cpp
if (Bluetooth::isConnected()) { … }      // 濾過的：要常呼叫
bool level = Bluetooth::readState();     // 腳位現在的電位
```

| | |
|---|---|
| 是什麼 | 模組的輸出：HC-05 的第 32 腳（LED2），配對前 LOW，電腦 / 手機連著時 HIGH；6 腳的 HC-06 板子一樣，或是 LED 的複本 |
| 接線 | 直接接任一腳，**不用分壓**（它是模組的輸出，3.3 V 進 UNO）；腳位到 GND 接 10 kΩ，板子沒把 STATE 接出來時會保持 LOW |
| 電位 | 3.3 V 對 UNO 算 HIGH（3.0 V 以上就是 HIGH），只剩 0.3 V 的餘裕：雜訊可能讓它翻掉 |
| 濾波 | `isConnected()` 要 STATE 持續 HIGH `CONNECTED_MS` 才變 true，持續 LOW `DISCONNECTED_MS` 才變 false：瞬間的突波、雜訊、跟著 LED 閃的 STATE 都不算 |
| 代價 | 連上晚 `CONNECTED_MS` 才知道，斷線晚 `DISCONNECTED_MS`；`init()` 後 `CONNECTED_MS` 內都是 false |
| 誰用它 | 程式（`1_HC_05.cpp` 只在它是 true 時轉送）；`HC06` 連線中拒絕 AT 命令（等 `GAP_MS` 的時候一直看 STATE） |
| 不接 | `NoPin`：`isConnected()` 是編譯錯誤；資料照樣通，只是板子分辨不出來 |

## 接線

| HC-05 | UNO | 說明 |
|---|---|---|
| VCC | 5V | 板子上的穩壓吃 3.6 ～ 6 V，做出模組要的 3.3 V |
| GND | GND | |
| TXD | **`BT_RX_PIN`**（或 D0） | 輸出 3.3 V：UNO 直接讀成 HIGH |
| RXD | 經分壓接 **`BT_TX_PIN`**（或 D1） | 模組吃 3.3 V：TX ─ 1 kΩ ─┬─ RXD，┬─ 2 kΩ ─ GND |
| EN | 任一腳（`EN_PIN`），經分壓 | 大部分板子是 KEY（HIGH = AT 命令），有些是電源開關（HIGH = 開）；HC-06：不接 |
| STATE | 任一腳（`STATE_PIN`），直接接（不用分壓），或不接 | 連線時 HIGH；見 [STATE](#state有沒有連線) |

```
BT_TX_PIN ──[1 kΩ]──┬── RXD        5 V × 2 / (1 + 2) = 3.3 V
                    └──[2 kΩ]── GND
```

- **改接 D0 / D1 時**（硬體 UART，和 USB 共用）：模組的 TXD 會在 D0 上和 USB 晶片打架，所以**上傳時要拔掉模組的 TXD（或 VCC）**，也不能同時用 `pio device monitor`。
- **電源**：等待或配對時約 30 ～ 40 mA，連線後約 8 ～ 10 mA：從 5V 腳供電，不要從一般腳位。
- **RXD 沒有上拉**：靠分壓電阻拉住；RXD 浮接會把雜訊當成資料。
- **靠近馬達時**：模組的 VCC 和 GND 之間加 100 nF + 10 µF，GND 用最短的線接 UNO 的 GND，TXD / RXD 遠離馬達線。

## 名稱

| 名稱 | 是什麼 |
|---|---|
| **SPP**（Serial Port Profile） | 溝通的方式：藍牙假裝成一條序列線（建在 RFCOMM 上）；電腦會多一個序列埠 |
| **HC-05** | 可以當主或從的模組，透過 EN（KEY，模組的第 34 腳）下 AT 命令，在 `module/HC_05.h` |
| **HC-06** | 只能當從的模組，只有沒連線時能下 AT 命令，在 `module/HC_06.h` |
| **EN / KEY** | 同一隻腳的兩個名字：HIGH = AT 命令模式；在 HC-06 上沒有作用；有些板子的 EN 反而是模組的電源開關 |
| **BLE**、**BT05** | 低功耗藍牙，和 SPP 不同的無線電：GATT service FFE0、characteristic FFE1；`module/BT05.h`（HM-10 那一類仿製品） |
| **STATE** | 連線時 HIGH（HC-05 是模組的第 32 腳） |
| **AT 命令** | 給模組自己的文字命令（`AT+NAME=…`）：名稱、PIN、鮑率、角色 |

依「`lib/` 以晶片或溝通方式命名」的規則：各家的晶片不同（CSR BC417 和它的仿製品），但每一個都是在 UART 上講 SPP，所以資料夾以溝通方式命名；其他 SPP 模組（JDY-31）會放進 `module/`。有透明 UART 的 BLE 模組（BT05、HM-10）也放這裡：板子這邊是同樣的 UART、同樣的封包；只有電腦那邊不同（`source/ble.py`）。

## 運作方式

| 步驟 | 傳統藍牙（HC-05、HC-06） |
|---|---|
| 1. 被找到 | 沒連線時，模組會聽「誰在附近？」（inquiry），回答自己的位址，再回答名稱 |
| 2. 配對 | 電腦要 PIN；雙方用 PIN、位址和亂數算出一把連結金鑰並存起來（PIN 本身不會送出去）：下次不用再輸入 PIN |
| 3. 連線 | 打開序列埠就連線（RFCOMM）；STATE 變 HIGH，LED 改變；關掉就斷線 |
| 4. 資料 | 雙向的位元組，UART 那邊是資料鮑率的 8N1 |

- **鮑率**只是板子和模組之間（UART）的速度；無線電有自己的速度。程式的 `BAUD` 和模組的資料鮑率必須一樣；電腦替藍牙序列埠設的鮑率沒有作用。
- **HC-05 的兩種 AT 模式**：上電時 EN 就 HIGH：38400 鮑，所有命令；上電後才把 EN 拉 HIGH：資料鮑率，大部分命令。`HC05` 用第二種，所以 UNO 的 UART 從來不換速度；連線中也能用。

## AT 命令

| 函式 | HC-05 | HC-06 |
|---|---|---|
| `check()` | `AT` | `AT` |
| `setName(name)` | `AT+NAME=name` | `AT+NAMEname` |
| `setPin(pin)` | `AT+PSWD=1234`，再試 `AT+PSWD="1234"`（韌體 3.0） | `AT+PIN1234` |
| `setBaud(baud)` | `AT+UART=baud,0,0`（`restart()` 後生效） | `AT+BAUDn` |
| `setRole(role)` | `AT+ROLE=n`：`ROLE_SLAVE`、`ROLE_MASTER`、`ROLE_SLAVE_LOOP` | — |
| `version(reply, size)` | `AT+VERSION?` | `AT+VERSION` |
| `restart()` | `AT+RESET` | — |
| `command(text, reply, size)` | 任何命令，加上 `\r\n` | 任何命令，原樣送出 |
| 結尾 | `\r\n` | 停頓（一秒最多一條命令） |

- **存在模組裡**：名稱、PIN、鮑率斷電後還在。
- **`setBaud` 之後**：模組下次啟動起用新的鮑率；程式的 `BAUD` 要改成一樣再上傳，不然雙方聽不懂彼此。
- **名稱**在以前配對過的電腦上可能還是舊的：在電腦上移除這個裝置再重新配對。

## 結果

| 結果 | 意思 | 常見原因 |
|---|---|---|
| `OK` | 模組接受了 | |
| `ERROR_NO_ANSWER` | 時間內沒有回答，或回答看不懂 | 程式的 `BAUD` 和模組的不一樣；TXD / RXD 接反；EN 沒接（HC-05）；HC-06 已經連線 |
| `ERROR_REFUSED` | 模組回答錯誤 | 這個韌體不認得的命令 |
| `ERROR_BAD_VALUE` | 值不允許：沒有送出 | 名稱太長或是空的、PIN 不是 4 位數字、鮑率不在清單裡 |
| `ERROR_CONNECTED` | 有 STATE 的 HC-06：已經連線，沒有送出 | 先斷線，或一上電就送命令 |

## 輸入限制

| 項目 | 範圍 | 超出時 |
|---|---|---|
| 名稱 | 1 ～ `MAX_NAME_LENGTH` 個可印字元 | 回傳錯誤（`ERROR_BAD_VALUE`） |
| PIN | 剛好 4 位數字 | 回傳錯誤（`ERROR_BAD_VALUE`） |
| HC-05 的 `setBaud` | 4800、9600、19200、38400、57600、115200、230400、460800、921600、1382400 | 回傳錯誤（`ERROR_BAD_VALUE`） |
| HC-06 的 `setBaud` | 1200、2400 和 HC-05 的清單 | 回傳錯誤（`ERROR_BAD_VALUE`） |
| `setRole` | `ROLE_SLAVE`、`ROLE_MASTER`、`ROLE_SLAVE_LOOP` | 回傳錯誤（`ERROR_BAD_VALUE`） |
| `HC05` 的 `Key` | 一隻腳 | 編譯錯誤 |
| 沒有 `State` 卻呼叫 `isConnected()`、沒有 `Key` 卻呼叫 `setCommandMode()` | | 編譯錯誤 |
| `Packet` 的 `MAX_LENGTH` | 1 ～ 255 | 編譯錯誤 |
| `UnoSerial` 的 `RX_SIZE`、`TX_SIZE` | 0，或 4 ～ 256 的 2 的次方；> 0 要 `Uno_serial_buffer.h` | 編譯錯誤 |
| 收到的封包的 LENGTH | 0 ～ `MAX_LENGTH` | 丟掉（`dropped()`） |
| `version`、`command` 的回答 | `size` - 1 個字元 | 截掉 |

## 注意事項

| 情況 | 結果 | 怎麼做 |
|---|---|---|
| 模組的 TXD 接在 D0 上時上傳 | 上傳失敗 | 上傳時拔掉 TXD（或 VCC），或用 `UnoSoftSerial` 接別的腳 |
| `UnoSoftSerial` 的 RX 腳和別的中斷腳同一組（紅外線接收器 D2、Echo D8） | 後 `init` 的拿走那組 | RX 放在自己一組（例如 A0 ～ A5） |
| 沒有緩衝區時 `loop()` 長時間在忙（畫螢幕、`delay`） | 位元組遺失：UNO 只存 2 個（9600 鮑約 2 ms）；`lostCount()`、`dropped()` 增加 | 用 `Uno_serial_buffer.h` 和 `RX_SIZE`；有緩衝區時，忙超過 `RX_SIZE` 個 byte 的時間還是會滿 |
| `brokenCount()` 增加 | 到板子 RX 的線上有雜訊，或 `BAUD` 不對 | 見[抗干擾](#抗干擾) |
| 上電時 HC-05 的 LED 慢閃 | 上電時 EN 是 HIGH：38400 的 AT 模式，沒有資料 | 上電時 EN 要 LOW（或不接）；`restart()` 一定以 EN LOW 結束 |
| 連線中重設 HC-06 | AT 命令變成文字送到電腦 | 接 STATE，或在電腦上忽略它們 |
| HC-06 的新 PIN 沒有作用 | 模組要斷電一段時間後才生效 | 拔掉一陣子 |
| 某個 HC-06 仿製品對 `check()` 沒有回答 | 「3.0-…」韌體要像 HC-05 一樣加 `\r\n` | `command("AT\r\n")`、`command("AT+NAME=x\r\n")` |
| iPhone | iOS 沒有 SPP：不能用 HC-05 / HC-06 | BLE 模組：`BT05` |
| BT05 從來不出現在電腦的藍牙設定裡 | 正常：BLE 不用配對、沒有序列埠 | `ble.py --scan`，再 `--ble NAME` |
| macOS 上 `ble.py` 什麼都找不到 | 終端機程式沒被允許使用藍牙 | 系統設定 → 隱私權與安全性 → 藍牙 |
| 板子還沒準備好電腦就送 | 遺失 | 等板子說準備好了（`round_trip.py` 會等 `[INFO] ready` 和連線） |
