# week_9_bluetooth

[English](README.md) | 中文

HC-05、HC-06（傳統藍牙）和 BT05（BLE）模組（[lib/bluetooth](../../lib/bluetooth/讀我.md)）的測試：來回一趟。電腦透過 USB 序列埠傳一行字給主板，主板從藍牙送出，再經由電腦的藍牙序列埠回到同一台電腦；反方向也可以。模組接在軟體 UART（`Uno::UnoSoftSerial`）上，所以 D0 / D1 留給 USB：模組接著也能上傳、用 USB 序列埠。

現在每個 `.cpp` 都是 `.bak`；留下要跑的那一個：

```bash
python src/hide.py week_9_bluetooth/tests/1_HC_05     # 只留這一個（去掉 .bak），其他變成 .bak
pio run -t upload
python src/week_9_bluetooth/tests/round_trip.py --bt /dev/cu.<NAME>     # HC-05 / HC-06（傳統）
python src/week_9_bluetooth/tests/round_trip.py --ble <NAME>            # BT05（BLE）：pip install bleak
```

是哪一種模組？先跑 `tests/3_diagnose.cpp`：`AT+UUID` 回 `+UUID=FFE0`（或 `4_BT05.cpp` 的 AT 回答）就是 BLE。

| 檔案 | 內容 | 需要的硬體 |
|---|---|---|
| `tests/1_HC_05.cpp` | 主板：透過 EN 設名稱和 PIN，然後當 USB ↔ 藍牙的橋；STATE 決定能不能送出 | HC-05（接 EN、STATE） |
| `tests/2_HC_06.cpp` | 一樣，但沒有 EN / KEY（AT 命令在一上電時送）、沒有 STATE（一律送出） | HC-06（4 腳） |
| `tests/4_BT05.cpp` | 同樣的橋，給 EN 是電源開關的板子上的 BT05 類 BLE 模組（`+UUID=FFE0`）：USB 上印名稱、PIN（6 位數）、韌體、位址 | BT05（接 EN、STATE） |
| `tests/3_diagnose.cpp` | 在 USB 上檢查接線和模組：EN 是 KEY 還是電源開關、TXD 那條線、STATE、每種鮑率的 `AT`（原始回答） | 模組，不需要電腦的藍牙 |
| `tests/round_trip.py` | 電腦：同時開 USB 和藍牙（`--bt 序列埠`）或 BLE（`--ble 名稱`），送出一行行文字，顯示每一行回來的時間、和送出的是否一樣 | Python 3，`pip install pyserial` |

## 接線

| 零件 | 腳 | UNO | 哪些程式 |
|---|---|---|---|
| HC-05 / HC-06 | VCC | 5V | 全部 |
| | GND | GND | |
| | TXD | **`BT_RX_PIN`** | |
| | RXD | 經 1 kΩ 接 **`BT_TX_PIN`**，RXD 再接 2 kΩ 到 GND | |
| HC-05 | EN | **`EN_PIN`**，經同樣的分壓 | `tests/1_HC_05` |
| | STATE | **`STATE_PIN`**，直接接 | `tests/1_HC_05` |
| USB | D0、D1 | 上傳、USB 序列埠 | 全部 |

| 腳 | 規則 |
|---|---|
| `BT_RX_PIN` | 任一腳；用它那組的腳位改變中斷（D0 ～ D7、D8 ～ D13、A0 ～ A5）：同一組不能有紅外線接收器（D2）或超音波 Echo（D8）；A0 ～ A5 兩個都沒有 |
| `BT_TX_PIN` | 任一腳，經分壓（模組吃 3.3 V） |
| `EN_PIN` | 任一腳，經分壓。EN 的作用看底板：大部分是 KEY（`EN_IS_POWER = false`：上電時 LOW，只有下 AT 命令時 HIGH），有些是模組的電源開關（`EN_IS_POWER = true`：一直 HIGH，LOW 會把模組關掉）。`tests/3_diagnose.cpp` 會告訴你是哪一種 |
| `STATE_PIN` | 任一腳，直接接（不用分壓：模組輸出 3.3 V）；板子可能沒把它接出來時，加 10 kΩ 到 GND |
| `BT_BAUD` | 模組的資料鮑率；兩種模組出廠都是 9600（軟體 UART 最高 38400） |

## 執行

1. 上傳（模組可以一直接著）。
2. 只有傳統模組（HC-05、HC-06）要：在電腦的藍牙設定配對模組：名稱是 `NAME`（以前配對過的電腦可能還顯示舊名稱：移除後重新配對），PIN 是 `PAIRING_PIN`。只要一次：電腦會記住。
3. 關掉 `pio device monitor`（一個序列埠只能一個程式用），然後：

```bash
python src/week_9_bluetooth/tests/round_trip.py --list                       # 列出序列埠：標出 USB 和藍牙
python src/week_9_bluetooth/tests/round_trip.py --bt /dev/cu.UnoKits          # macOS；Windows：--bt COM5（傳出）
python src/week_9_bluetooth/tests/round_trip.py --bt /dev/cu.UnoKits --count 100   # 自己送 100 行，最後統計
```

只有插著不只一個 USB 序列埠時才需要 `--usb`。

**BLE（`4_BT05.cpp`）**：不用配對，模組也不會出現在藍牙設定或 `/dev/cu.*`；`round_trip.py --ble TanksUno` 用名稱找到它（先 `pip install bleak`；macOS 第一次會要求允許終端機程式使用藍牙）。`python lib/bluetooth/source/ble.py --scan` 列出附近的裝置。手機連著模組時它不會廣播：先在手機上斷線。

## 執行流程

```
  電腦（round_trip.py）                   USB 序列埠          UNO（1_HC_05.cpp）              藍牙
  ─────────────────────                   ──────────          ──────────────────              ────
  打開 USB 序列埠  ────────────────────── DTR 重設 ─────────▶ setup()：對模組下 AT 命令
  [BOARD] [INFO] AT: OK …            ◀──────────────────── 印出每個結果
  [BOARD] [INFO] ready …             ◀────────────────────
  打開藍牙序列埠 ─────────────────────────────────────────────────────────────────────────▶ 連線，STATE HIGH
                                                            loop()：CONNECTED_MS 後 isConnected() 變 true
  你打：hello
    "hello\n"  ─────────────────────────────────────────▶ readUsb()：位元組 → 一行
                                                            forwardLine()：封包 'T' "hello" ──▶ 模組 ~~▶
  [BOARD] [TO BLUETOOTH] hello       ◀────────────────────  印出                                           │
  read_bt：Decoder → 'T' "hello"     ◀~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~┘
  [BACK] "hello" 52 ms, same

  你打：< hi
    封包 'T' "hi" ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~▶ 模組 ──▶ BT_RX_PIN
                                                            中斷：邊緣 → 位元組 → 緩衝區
                                                            packets.update()：CRC 正確 → showPacket()
  [BOARD] [FROM BLUETOOTH] hi        ◀────────────────────  印出
  [BACK] "hi" 40 ms, same
```

**電腦（`tests/round_trip.py`）**：

1. 找到主板的 USB 序列埠（唯一一個不是藍牙的 USB 序列埠），以 `MONITOR_BAUD` 打開。打開會重設主板，所以先等主板的 AT 結果和 `[INFO] ready`，每一行印成 `[BOARD] …`。
2. 打開藍牙序列埠：在藍牙上，打開就是連線。稍等一下，讓主板的 STATE 濾波反應。
3. 兩個執行緒一直在讀：
   - **USB**：主板印的每一行 → `[BOARD] …`；`[FROM BLUETOOTH] text` 這行代表一趟「藍牙 → USB」結束。
   - **藍牙**：位元組送進 `Decoder.feed()`（`lib/bluetooth/source/packet.py` 的 START、LENGTH、COMMAND、DATA、CRC-8）；封包 `'T'` 代表一趟「USB → 藍牙」結束；壞掉的封包跳過並印 `[WARNING]`。
4. 主執行緒等你打一行：
   - `hello` → 寫進 USB：`hello\n`，記下時間。
   - `< hello` → 寫進藍牙：封包 `'T'`（`encode()`），記下時間。
5. 一行回來時，和那個方向最早送出、還沒回來的那一行比對：
   - `[BACK] "hello" 52 ms, same`：回來了，沒變，來回 52 ms。
   - `[ERROR] … different`：回來了但變了（有 CRC 擋著，不該發生）。
   - `[ERROR] … not back in 2.0 s: lost`：沒回來（沒連線、封包壞掉、主板沒在跑）。
6. `--count N`：一行接一行送 N 行隨機文字（上一行回來或遺失後才送下一行），最後印 `[INFO] N sent: … same, … different, … lost` 和最短、最長、平均的來回時間。
7. Ctrl+C 關掉兩個序列埠：藍牙斷線。

**主板（`tests/1_HC_05.cpp`）**：

1. `setup()`：USB 序列埠（有緩衝區：`Uno_serial_buffer.h`）；`packets.init()` 啟動軟體 UART（TX HIGH、RX 中斷）、EN LOW、STATE；AT 命令（`check`、`setName`、`setPin`、`version`），每個結果印在 USB；最後 `[INFO] ready`。
2. `loop()` 每一圈，都不會等：
   - `isConnected()`：濾過的 STATE；改變時印 `[INFO] connected` / `disconnected`。
   - `readUsb()`：拿 USB 中斷收好的位元組；`\n` 結束一行（`\r` 丟掉，超過 `LINE_MAX` 截掉）。`forwardLine()`：沒連線 → `[ERROR] not connected`；不然從藍牙 `packets.send('T', line)`（每個位元組約 1 ms），USB 上印 `[TO BLUETOOTH] line`。
   - `packets.update()`：拿軟體 UART 中斷收好的位元組；收到一整個 CRC 正確的封包 → `showPacket()`：`'T'` → USB 上印 `[FROM BLUETOOTH] text`，其他 → 印它的命令和長度。
   - `printErrors()`：丟掉的封包、壞掉 / 遺失的位元組數有變時才印一行 `[WARNING]`。
3. 同時在背景：主板忙著從藍牙送出時，USB 中斷先把電腦送來的位元組收起來（`USB_RX_BUFFER`）；`BT_RX_PIN` 的每個邊緣都會跑軟體 UART 的中斷（幾 µs），用邊緣之間的時間算出位元，每個完整的位元組收起來（`BT_RX_BUFFER`）。

`tests/2_HC_06.cpp` 一樣，只是沒有 EN（AT 命令只在還沒連線時有效，每條約一秒），也沒有 STATE（沒有 `connected` 的行；不管有沒有連線都送出）。

## 顯示的內容

```
[BOARD] [INFO] HC-05: module TXD -> A0, RXD <- A1, EN <- D12, STATE -> D4, 9600 baud
[BOARD] [INFO] AT: OK
[BOARD] [INFO] AT+NAME: OK
[BOARD] [INFO] AT+PSWD: OK
[BOARD] [INFO] AT+VERSION?: OK
[BOARD] [INFO] firmware 2.0-20100601
[BOARD] [INFO] ready: pair "UnoKits", open its serial port, then type lines here
[INFO] opening /dev/cu.UnoKits (this connects Bluetooth)
[BOARD] [INFO] connected
[SUCCESS] both open: type a line (USB -> Bluetooth), or "< line" (Bluetooth -> USB); Ctrl+C ends
hello
[BOARD] [TO BLUETOOTH] hello
[BACK] "hello" 52 ms, same
< hi
[BOARD] [FROM BLUETOOTH] hi
[BACK] "hi" 40 ms, same
```

| 行 | 來自 | 意思 |
|---|---|---|
| `[BOARD] …` | 主板，經 USB | 它的紀錄：AT 結果、`connected`、轉送了什麼 |
| `[BOARD] [TO BLUETOOTH] hello` | 主板 | 這行從 USB 進來，以封包 `'T'` 送出去了 |
| `[BOARD] [FROM BLUETOOTH] hi` | 主板 | 從藍牙收到一個 CRC 正確的封包 `'T'` |
| `[BACK] "…" N ms, same` | `round_trip.py` | 這行到了另一端，沒變，送出後 N ms |
| `[ERROR] … different` / `lost` | `round_trip.py` | 變了 / 沒到 |
| `[BOARD] [WARNING] packets dropped …, bytes broken …, bytes lost …` | 主板 | dropped：封包在路上壞掉；broken：到 `BT_RX_PIN` 的線上有雜訊或 `BT_BAUD` 不對；lost：緩衝區不夠 `loop()` 忙的那段時間用 |

- **來回時間**：主要是以 `BT_BAUD` 送出（每個位元組約 1 ms，封包多的 4 個位元組也算），加上藍牙連線本身（幾十 ms）。
- **`AT: no answer`**：EN 沒接或沒經分壓、TXD / RXD 接反（模組 TXD → `BT_RX_PIN`）、或 `BT_BAUD` 不是模組的鮑率。
- **`AT+VERSION?: refused` 但其他都 OK**：有些韌體在這個 AT 模式不回答 `AT+VERSION?`；沒關係。
- **主板印 `[ERROR] not connected (STATE LOW)`**（HC-05）：藍牙序列埠沒打開，或 STATE 沒接。
- **HC-06 全部 `lost`**：沒有 STATE 可以判斷，沒連線也會送出：先打開藍牙序列埠。
- **用 `pio device monitor` 取代 `round_trip.py`**：也可以（打一行就從藍牙送出），但沒有人比對、計時回來的東西。
- **HC-06**：新的 PIN 要模組斷電一段時間後才生效；「3.0-…」韌體的仿製品要加 `\r\n`：用 `Module::command(...)`。
